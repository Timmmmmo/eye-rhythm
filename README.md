# 对视 · Eye Rhythm — MVP

> 用手机前置摄像头陪你练「眼神节奏」：一天 3 分钟，把稳视时长和节奏变成看得见的曲线。
> 面试、相亲、述职之前，先练 3 天。

**在线试玩：https://timmmmmo.github.io/eye-rhythm/**
（手机浏览器直接打开；摄像头需要 https，GitHub Pages 自带，所以真机可用。
不开摄像头也能玩——按住屏幕就算"注视"。）

这是《对视训练_逻辑诊断与商业计划书.md》里那套改造方案的**可运行验证版**。
目标不是 demo 好看，是**把三条核心主张变成可以被跑起来的机制**。

## 一、这个 MVP 到底在验证什么

方案里最关键的一刀是：**目标不该是「敢看」，而是「会看」。**

人对视超过约 4 秒会生理性不适——这是普遍现象，不是病。所以：

| 主张 | 在代码里怎么落地 | 怎么验证 |
|---|---|---|
| **撑得久不等于好** | 注视 2.2–3.8s = 满分窗；>4s 扣分并触发"对方不适"；超出舒适窗的时长额外惩罚（最高 −60%） | 仿真：一路盯 60 秒 = **21 分**；看 3 秒移 1 秒 = **100 分** |
| **对视必须是双向的** | 互惠反馈状态机：你不上心它就松弛（relax），你稳视它微点头（reward），你超时就皱眉后仰（uncomfortable），再超时它先移开（avoid） | 断言：按住 2.5 秒 → HUD 进「奖励态」；超 4 秒 → 「不适」 |
| **进步要看得见** | 端侧眼神追踪 → 稳视时长 / 命中率 / 游离次数 / 眨眼频率 → 每日曲线 | 真机 Edge 实测（见下方验收输出） |
| **隐私是前提不是免责** | 全程本机推理，画面不落盘、不上传、不留帧 | 验收脚本检查外部请求清单 |
| **不开摄像头也得能用** | 三级降级：摄像头坏了 / 没权限 / 模型没下下来 → 按住屏幕 = 注视 | 断言：非 ready 状态下按压即生效 |

### 模块一：眼神节奏训练（主线，做留存）

- 6 级难度阶梯：卡通 → 半写实 → 写实 → 会眨眼 → 会游移 → 有表情 → 有态度
- 单轮 90 秒，实时 HUD：当前注视时长 / 目标 3s / 命中率 / 状态提示
- 复盘给出**具体建议**（不是分数就完事）：命中率太低 / 每次都多看一眼 / 眨眼过快像紧张
- 紧张自动降档：游离率高 + 命中率低 → 弹 **4-7-8 呼吸引导** 15 秒，然后回到同级重试
- 解锁规则：单轮 ≥ 60 分过线

### 模块二：眼力游戏（传播引擎，做拉新）

**输出（稳视）做留存，输入（读眼）做传播。**
训练模块涉及摄像头和隐私，天生不适合分享；眼力模块纯游戏、有分数、不碰隐私，可以随便晒。

- 10 种眼神语义：好奇 / 审视 / 厌烦 / 尴尬 / 温柔 / 惊讶 / 愤怒 / 悲伤 / 怀疑 / 紧张
- 每种都由**可解释的几何特征**定义（眉高 / 眉角度 / 眼睑开合 / 下眼睑收紧 / 瞳孔 / 视线 / 不对称 / 潮红出汗）
- 10 题 4 选 1，干扰项从"易混对"里取（审视↔愤怒↔怀疑），答完给解析

### 模块三：动物挑战（传播钩子）

猫 → 狼 → 虎，全程直视你，**越久越压迫**（瞳孔收缩 + 眉压 + 缓慢逼近）。
"你能和它对视几秒？"——视觉冲击 + 对抗感 + 分数 + 不涉及隐私。可生成分享卡。

## 二、跑起来

```bash
# ① 最省事：直接打开线上地址（手机也能开，摄像头直接可用）
#    https://timmmmmo.github.io/eye-rhythm/

# ② 本地双击（无摄像头，走按压模式，全部玩法可玩）
mvp/index.html

# ③ 本地要用摄像头：必须 https 或 localhost（浏览器安全策略）
npx serve mvp         # 然后开 http://localhost:3000
```

摄像头链路：`getUserMedia` → MediaPipe Face Landmarker（WASM，**本地推理**）。

**首次打开要有耐心**：模型 + WASM 约 3MB，线上冷缓存实测**约 17 秒**才进入真实追踪。
这 17 秒里界面不会卡 —— 按住屏幕 = 注视，照样能练。而且**首页停留 1.2 秒后就开始静默预热模型**，
等到你点「开始」，模型基本已经就绪（预热只下模型、**不申请摄像头，所以不会一进首页就弹权限框**）。
省流量模式（`saveData`）或 2G 网络下会自动跳过预热。

国内网络如果拉不到 `storage.googleapis.com`，把 `js/track.js` 里的 `MODEL_URL` 换成可达镜像即可。

## 四、验收结果（真机 Edge，非静态检查）

```
60 通过 / 0 失败 · 运行时报错 0 条
（本地 `node _dev/cdp-check.js` 与线上 `CHECK_URL=https://timmmmmo.github.io/eye-rhythm node _dev/cdp-check.js` 都跑同一套）

【核心主张】
  ✅ 看3秒+移开 得分 > 一路盯着 60 秒        →  ideal=100  vs  stare=21
  ✅ 节奏分：3秒节拍 > 死盯                  →  100        vs  12
  ✅ 死盯 60 秒触发超时惩罚                  →  penalty=0.6 · 超时 56s
  ✅ 每次多看一眼（5秒）分数介于两者之间      →  57（惩罚是渐进的，不是一刀切）
  ✅ 整轮没看 → 0 分；一直游离 → 0 分
  ✅ 死盯不放也算 1 轮（不会被统计成「一次都没看」）

【互惠反馈状态机】
  ✅ 没看=relax  刚看上=engage  0.8~4s=reward  >4s=uncomfortable  >6s=avoid

【渲染】
  ✅ 脸占 35.7% 不透明像素 · 左右眼深色像素 32326/32542（高度对称）
  ✅ 脸完整落在画布内 [129,183,646,945]
  ✅ 画布尺寸 = CSS 尺寸 × dpr，反复绘制不涨，且不溢出卡片

【空状态】
  ✅ 无数据时大分数是"实色可见的灰蓝破折号"，不是透明隐形、也不是被背景渐变透出的一根亮条
  ✅ 曲线区文案在 DOM 里（不在 260×70 的 canvas 里 —— 那边会被目标线裁掉）

【预热与降级】
  ✅ 有静默预热接口 track.warm()
  ✅ 预热阶段没有偷开摄像头（首页不该弹权限框）
  ✅ 预热阶段状态仍是 idle（没假装已就绪）
  ✅ 摄像头就绪后走真实追踪；非 ready 时「按住=注视」生效
  ✅ 外部请求仅 4 条（模型/WASM），无任何行为数据上报
```

复跑（本地）：`node _dev/cdp-check.js`
复跑（线上，发布后终验）：`CHECK_URL=https://timmmmmo.github.io/eye-rhythm node _dev/cdp-check.js`
两个都会自己起 Edge、自己截图；线上模式还会额外断言"除模型 CDN 外没有任何第三方请求"。

### 本轮修掉的坑（都是"看着能跑、其实在真机上会翻车"的那类）

| 坑 | 症状 | 根因 |
|---|---|---|
| **画布被 dpr 反复放大** | 首页曲线图放大 2 倍、撑出卡片，图上文字跟着糊掉 | `fitCanvas` 按 `rect × dpr` 设 backing store，而 `#spark` 没有 CSS 宽高 → 改 `width` 属性反过来改了布局尺寸，量一次乘一次。`#stage` 因为 CSS 写了 `100%` 才幸免 |
| **空状态是"隐形破折号"** | 无数据时大分数位置有时看不见、有时是一根亮条 | `.empty` 挂在了里面的 `span` 上，而规则是 `.score-big.empty`（父元素）→ 永不匹配；同时 `background-clip:text` 把渐变从字形里透了出来 |
| **提示条压住弹层正文** | "新纪录 2.8s" 盖在「3 秒法则」最后一行上 | `.toast` 的 `z-index:60` 高于 `.sheet` 的 `50` |
| **复盘建议数字自相矛盾** | 上面写"最长注视 5.9 秒"，下面写"你一共盯着不放 1.9 秒" | 文案把"超出 4 秒舒适窗的部分"说成了总时长 |
| **睫毛像被刮出来的痕迹** | 3 倍放大下一只眼睛 7 根等长睫毛铺满整条睑缘 | 数量/长度按卡通风格放大后失真 |
| **首次进训练要干等 17 秒** | 线上冷缓存下摄像头从 loading 到 ready 实测 17293ms | 模型 3MB + WASM，只在点进训练时才懒加载。改成首页 idle 1.2s 后**静默预热**（只下模型不开摄像头） |

这 6 条里有 3 条（画布放大、空状态、提示条遮挡）**截图上一直存在，但断言查不到** —— 所以本轮把断言补成了 60 条，
新增的都是"尺寸 / 可见性 / 遮挡关系 / 有没有偷开摄像头"这类能被机器判定的项，而不是靠人眼盯截图。

## 五、已知限制（说清楚，别装作没有）

### 1. ★ 脸不够真 —— 这是产品最大的真实风险

`face.js` 是**纯矢量程序化绘制**，出来的是"精致的人体模特"，不是真人。
而产品的全部心理机制建立在**被评价的压力**上；模特脸的压力接近于零。

所以现状是：**机制可以验证，压力感还不成立。**

生产环境的正确解法（接口已经留好了）：
`face.js` 对外暴露的是 `draw(ctx, W, H, ch, anim)`，其中 `anim` 就是
`gazeX/gazeY/lidOpen/lowerLid/browRaise/browAngle/browAsym/pupil/headYaw/headPitch/headRoll`
——**这正是 blendshape / 骨骼驱动的人头需要的参数集**。
后续把 `face.js` 换成"带 blendshape 的写实 3D 头（GLB）"或"授权的高清人像视频素材"，
`session.js` 与 `track.js` 一行都不用改。

优先级建议：**先换脸，再谈投放**。否则用户练完在现实里不会有变化，口碑会崩。

### 2. 眨眼计数在降级模式下恒为 0

按压模式没有摄像头，`ear` 拿不到，所以"眨眼/分"这个紧张指标在无摄像头时无意义。真实追踪下正常。

### 3. 眼神追踪是浏览器端近似

用虹膜相对眼角的位置估视线，用两眼宽度差估头部偏转——够用，但不如专业眼动仪。
侧脸、逆光、戴粗框眼镜会掉精度。

### 4. 标准分位是模型估算

眼力游戏的"前 X%"按 10 题均值 5.2、标准差 1.8 的正态模型算，**不是真实人群抽样**。界面上已标注。

### 5. 没有账号，也就没有服务端

曲线和纪录只存在本机 `localStorage`。换手机、清缓存就没了；也因此做不了排行榜、做不了防作弊、做不了多端同步。

这是**刻意的取舍**（隐私优先 + MVP 阶段先验证机制），但要做留存和传播，这一块必须补——
而且补的时候要小心：一旦数据上云，"你的脸不出你的手机"这句话就得重新组织表述。
建议只上传**分数与时长**，永不上传画面或人脸特征，把这条写进隐私政策而不是藏在设置里。

## 七、隐私说明（给用户看的原文）

> **你的脸，永远不出你的手机。**
> 画面只在本机内存里过一遍：不落盘、不上传、不留帧、不做人脸辨识。
> 模型只下载一次，推理全在你的浏览器/手机里完成。
> 你可以随时关掉摄像头——动物挑战和眼力游戏完全不需要它。

工程上也确实如此：`track.js` 拿到 `stream` 后只喂给本地 WASM 推理，
没有任何 `fetch`/`XHR` 把人像数据发出去；验收脚本会检查外部请求清单。
